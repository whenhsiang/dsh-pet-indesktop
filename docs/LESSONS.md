## 2026-11-15 · 文本替换删除代码行会「咬掉」不同缩进位点的空格

**现象**：用 `text.replace('        self._x(...)\n', '')` 批量删 8 空格缩进的
调用行，结果 16/12 空格缩进的同名调用也被部分匹配——模式串是它们的子串，
删掉后残留前导空格与下一行拼接，制造 `Unexpected indentation`（window.py
一次断在两处，靠 ruff 的 invalid-syntax 才抓到）。

**对策**：① 删代码行优先按「上一行 + 目标行 + 下一行」三行锚点整块替换并
`assert count == 1`；② 任何脚本化文本 surgery 后立即 `py_compile` +
`ruff check` + `pytest --collect-only -q`（合计 ~20 秒），不合格绝不进全量。

## 2026-11-15 · 全量测试运行期间不得编辑任何 .py

**现象**：pytest 跑到一半编辑产品文件（哪怕只删一个 import 行），
`inspect.getsource` 探针按导入时记录的行号去读已位移的源码，假报
「找不到 reload 白名单元组」——6 个假失败，单文件复跑全绿。

**对策**：测试跑动期间只做只读侦察；要改文件就等收口。发现「批量同类探针
失败」先怀疑行号位移，不要急着改产品代码。

## 2026-11-15 · 删函数要删干净：残留的空 def 会炸整个收集

**现象**：删除 win-only 测试时留了 `def test_xxx():  # 已移除` 空函数体，
`IndentationError` 使 pytest 收集整体中断（63 个收集错误）。

**对策**：删测试 = 删完整函数（含 docstring 与装饰器）；删完跑
`--collect-only` 确认。空 def 即使只有 docstring 语法合法，也不要留——它是
假信号。

## 2026-11-15 · 注入时钟必须覆盖所有时间路径（定时炸弹测试）

**现象**：`ChatMemory` 写路径走注入 `clock`，但 `load()` 的读副本巡检用真实
墙钟——测试冻结 `NOW=2026-10-21`，23 天后（>14 天归档窗口）任何机器上该用例
必红。同一文件里第二颗同型炸弹 28 天后爆。

**对策**：给类注入 clock/探针时，grep 该文件所有 `datetime.now()`，逐一核对
读路径是否同源；生产默认值必须与原表达式逐位一致（行为不变），改动后跑该
文件全量。

## 2026-11-15 · 上游依赖的数据边界不要在测试里钉死具体日期

**现象**：`lunar-python` 1.4.9 内嵌国务院 2027 节假日安排，测试把「安排表
之外」钉死在 2027-01-01 → 两个用例红。requirements 只约束 `>=1.4.8`，CI 与
本地拿到的版本随时间漂移。

**对策**：「边界/表外/耗尽」类语义用替身注入（monkeypatch + 进出清
`lru_cache`），真表内的稳定断言保留；产品 docstring 不写「覆盖到某年」这类
随版本漂移的事实。

## 2026-11-15 · 删除模块前先全仓 `--collect-only` 枚举收集错误

**现象/对策**：删了 `tools/mem_probe.py` 后，唯一真收集错误是
`tests/test_mem_probe_census.py` 的 import；`pytest --collect-only -q` 全仓
14 秒就能枚举全部 import 断裂，比跑全量便宜两个数量级。每批删除的 T1 快门
必含这一步。

## 2026-11-15 · pytest-xdist 并行全量实测 7 倍提速且未 flake

**现象**：8582 例串行 12:12，`-n auto`（10 核）1:47，零失败；删除批次
8571 例 1:43 同样全绿。

**对策**：批次级收口默认 `-n auto`（T2）；时序族若在 T2 偶发红，先隔离复跑
判定真伪，连续 flake 才降级回串行（对齐 AGENTS.md CI 纪律：不赌时序）。注意
xdist 下 conftest 的进程级全局（如 feature_activation 快照）按 worker 各一份，
依赖跨用例全局状态的用例若出问题先查这条。
